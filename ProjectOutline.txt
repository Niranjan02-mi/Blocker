 # 🛡 *BlockKlear – Decentralized KYC Workflow Platform*

*Tagline:* "Decentralized, Verifiable, Trustless Identity Verification"

---

## ✅ 1. *Problem Statement*

Traditional KYC systems are centralized, prone to data leaks, and lack public verifiability. Organizations can't trust shared KYC unless it’s backed by a tamper-proof system.

---

## 🎯 2. *Objective*

Use *Orkes Conductor* to orchestrate a modular KYC process involving:

* Off-chain: Document, biometric, and compliance verification
* On-chain: Storing the final result as a *SHA-256 hash* on *Ethereum/Polygon testnet*

The system must ensure *data privacy, **user control, and **verifiability*.

---

## 🔍 3. *User Flow (UX Perspective)*

### 👤 Step-by-Step (User Journey)

1. *User lands on BlockKlear dashboard*
2. *Connect MetaMask wallet* (optional but recommended)
3. *Begin KYC process:*

   * Upload ID → OCR → Face Match → Compliance Check
4. *On approval:*

   * System generates hash of verified KYC data
   * User confirms MetaMask transaction → Hash stored on blockchain
5. *KYC Complete:*

   * View transaction link
   * Download QR code
   * Status marked: “✅ Verified on Blockchain”

## 🔗 4. *System Architecture Overview*

### 📦 *Core Components*

#### A. Frontend (React-based UI)

* Wallet connection (MetaMask)
* Real-time progress steps
* Upload & webcam integration
* Status dashboard with on-chain links

#### B. Backend (Node.js + Orkes Conductor)

* Orchestrates steps:

  * OCR service
  * Face verification
  * Compliance API call
  * Result evaluation

#### C. Blockchain Layer

* Solidity Smart Contract: stores bytes32 hash
* Network: Ethereum Goerli or Polygon Mumbai
* Interaction: via ethers.js

## 🔁 7. *KYC Workflow Steps (Technical)*

| Step | Task                            | Type        |
| ---- | ------------------------------- | ----------- |
| 1    | Upload ID document              | Off-chain   |
| 2    | OCR extraction                  | Off-chain   |
| 3    | Face match with document        | Off-chain   |
| 4    | Compliance check (e.g. PEP/AML) | Off-chain   |
| 5    | Generate verification hash      | Hybrid      |
| 6    | Store hash on blockchain        | On-chain    |
| 7    | Provide TX link + QR            | UI/On-chain |

Orkes Conductor handles this as a chained microservice workflow.

---

## 📊 8. *Smart Contract Function*

Simple KYCHashStore.sol:

solidity
mapping(address => bytes32) public kycHash;
function storeKYC(bytes32 _hash) public {
    kycHash[msg.sender] = _hash;
}


* Allows any verified user to store their own KYC hash
* Can be extended to emit events, verify by admin, etc.
